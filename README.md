# ربات معاملاتی تلگرام خرید و فروش ارز (DanmarkFinanceBot)

این پروژه یک ربات هوشمند و پیشرفته تلگرام برای ایجاد محیطی جهت خرید و فروش ارز در گروه‌های تلگرامی است. فرآیند ثبت پیشنهادها به صورت خصوصی و گام‌به‌گام انجام شده و پس از تایید به همراه دکمه‌های تعاملی شیشه‌ای به گروه معاملاتی ارسال می‌گردد. کاندیدهای معامله با کلیک روی دکمه شیشه‌ای مستقیماً به پی‌وی ربات هدایت شده و ربات هر دو طرف را به ادمین جهت نهایی‌سازی و تایید معامله ارجاع می‌دهد و اطلاعات کامل طرفین را برای ادمین ارسال می‌کند.

پروژه به طور کامل با **TypeScript**، **Telegraf**، **Prisma ORM** و **PostgreSQL** توسعه یافته و برای اجرا درون **Docker** و استقرار در **DigitalOcean** آماده شده است.

---

## 🛠 ویژگی‌های کلیدی
- **جریان ثبت پیشنهاد گام‌به‌گام (Wizard Scene):** راهنمای فارسی روان برای وارد کردن نوع معامله، نوع ارز، مقدار و قیمت.
- **ثبت معاملات در دیتابیس:** ذخیره کامل تاریخچه کاربران، پیشنهادها و معاملات انجام شده.
- **سیستم پیوند عمیق (Deep Linking):** انتقال امن خریداران/فروشندگان از گروه به چت خصوصی ربات بدون افشای عمومی آیدی‌ها.
- **بروزرسانی خودکار پیام گروه:** به محض پذیرش یا لغو پیشنهاد، وضعیت پیام در گروه تلگرام ویرایش شده و به «معامله شد» یا «لغو شد» تغییر می‌یابد.
- **کانتینرایز شده (Dockerized):** راه‌اندازی سریع محیط توسعه و تولید با استفاده از Docker Compose.

## 🚀 راهنمای راه‌اندازی محلی (Development)

### پیش‌نیازها
- نصب [Docker](https://www.docker.com/) و Docker Compose.
- یا نصب Node.js (نسخه ۲۰ یا بالاتر) و PostgreSQL به صورت محلی.

### ۱. تنظیم متغیرهای محیطی
ابتدا فایل نمونه متغیرهای محیطی را کپی کرده و مقادیر مربوطه را وارد کنید:
```bash
cp .env.example .env
```
متغیرهای درون فایل `.env` را به شکل زیر ویرایش کنید:
- `BOT_TOKEN`: توکنی که از [BotFather@](https://t.me/BotFather) دریافت کرده‌اید.
- `BOT_USERNAME`: یوزرنیم ربات شما بدون `@` (مثال: `DanmarkFinanceBot`).
- `GROUP_CHAT_ID`: آیدی عددی گروه تلگرام شما. برای دریافت آن می‌توانید ربات را به گروه اضافه کرده و پیام تستی بدهید، سپس از ربات‌های دریافت آیدی مانند `RawDataBot@` استفاده کنید (آیدی گروه‌ها معمولاً با `-100` شروع می‌شود).
- `DATABASE_URL`: آدرس اتصال به پایگاه داده. برای اجرای محلی با داکر نیازی به تغییر ندارد.
- `ADMIN_USERNAME`: یوزرنیم تلگرام ادمین (بدون @) جهت نمایش به خریدار و فروشنده.
- `ADMIN_CHAT_ID`: آیدی عددی تلگرام ادمین. (نگه داشته شده برای سازگاری؛ مقدار پیش‌فرض دو متغیر زیر است.)
- `ADMIN_NOTIFY_CHAT_ID`: مقصد ارسال اعلان‌های مدیریتی. این یکی **می‌تواند آیدی گروه باشد**.
- `BOOTSTRAP_ADMIN_ID`: ادمینی که همیشه شناخته می‌شود و می‌تواند بقیه ادمین‌ها را اضافه کند. این مقدار **حتماً باید آیدی یک کاربر باشد، نه گروه**؛ چون آیدی گروه هرگز با فرستنده پیام برابر نمی‌شود و قبلاً همین موضوع باعث می‌شد تنظیم گروه، تمام دکمه‌های مدیریتی را از کار بیندازد.

### ۲. اجرای پروژه با داکر (سریع‌ترین روش)
دستور زیر را در پوشه پروژه اجرا کنید تا دیتابیس PostgreSQL و ربات تلگرام ساخته و اجرا شوند:
```bash
docker compose up --build -d
```
این دستور:
1. ایمیج ربات را بیلد می‌کند.
2. دیتابیس PostgreSQL را بالا می‌آورد.
3. مایگریشن‌های نسخه‌بندی‌شده موجود در `prisma/migrations` را با دستور `prisma migrate deploy` اعمال می‌کند.
4. ربات را اجرا کرده و شروع به شنود پیام‌ها می‌کند.

برای مشاهده لاگ‌های اجرای ربات:
```bash
docker compose logs -f bot
```

### ۳. متوقف کردن پروژه
```bash
docker compose down
```

## ☁️ راهنمای استقرار در دیجیتال‌اوشن (DigitalOcean)

شما می‌توانید پروژه را به دو روش در دیجیتال‌اوشن بالا بیاورید:

### روش اول: استفاده از App Platform (پیشنهادی و کاملاً مدیریت‌شده)
دیجیتال‌اوشن در این روش وظیفه بیلد، اجرا، گواهینامه SSL و نگهداری برنامه را بر عهده می‌گیرد.
1. یک ریپازیتوری خصوصی یا عمومی در گیت‌هاب بسازید و کدهای پروژه را روی آن پوش (`git push`) کنید.
2. وارد پنل دیجیتال‌اوشن شده و روی دکمه **Create** و سپس **Apps** کلیک کنید.
3. منبع را گیت‌هاب انتخاب کرده و ریپازیتوری خود را متصل کنید.
4. دیجیتال‌اوشن فایل `Dockerfile` را شناسایی می‌کند.
5. در بخش **Resources**، می‌توانید یک پایگاه داده **Dev Database** (که PostgreSQL است) اضافه کنید. دیجیتال‌اوشن به صورت خودکار متغیر `DATABASE_URL` را ایجاد و به اپلیکیشن متصل می‌کند.
6. در بخش **Environment Variables**، متغیرهای زیر را وارد کنید:
   - `BOT_TOKEN`
   - `BOT_USERNAME`
   - `GROUP_CHAT_ID`
   - `ADMIN_USERNAME`
   - `ADMIN_CHAT_ID`
7. روی دکمه **Create Resources** کلیک کنید. فرآیند ساخت و بیلد آغاز شده و ربات شما در عرض چند دقیقه آنلاین می‌شود.

### روش دوم: استفاده از سرور مجازی (Droplet)
اگر ترجیح می‌دهید یک سرور ابری معمولی داشته باشید:
1. یک Droplet با سیستم‌عامل Ubuntu در دیجیتال‌اوشن بسازید.
2. ابزارهای Docker و Docker Compose را روی سرور نصب کنید.
3. کد پروژه را از طریق گیت روی سرور کلون کرده یا آپلود کنید.
4. فایل `.env` را روی سرور بسازید و مقادیر را پر کنید.
5. دستور زیر را روی سرور اجرا کنید تا ربات به صورت دائمی در پس‌زمینه اجرا شود:
   ```bash
   docker compose up -d --build
   ```

## 🗃 ساختار پایگاه داده (Prisma Schema)

ربات از سه جدول اصلی برای مدیریت معاملات استفاده می‌کند:
- **User (کاربران):** ذخیره اطلاعات کاربرانی که با ربات تعامل داشته‌اند (آیدی تلگرام، نام و یوزرنیم).
- **Proposal (پیشنهادها):** ثبت درخواست‌های ثبت شده خرید/فروش (نوع، نوع ارز، مقدار، قیمت واحد، وضعیت معامله و آیدی پیام ارسالی در گروه).
- **Deal (معاملات):** ثبت معاملات قطعی شده بین خریدار و پذیرنده پیشنهاد همراه با تاریخچه.
- **CounterOffer (پیشنهادهای قیمت):** پیشنهادهای قیمت جدیدی که کاربران برای یک آگهی ثبت می‌کنند.
- **Admin (مدیران):** فهرست ادمین‌ها با نقش (`VIEWER` / `OPERATOR` / `OWNER`). تشخیص هویت ادمین از این جدول انجام می‌شود، نه از مقایسه با یک آیدی ثابت.
- **AuditEvent (گزارش عملیات):** ثبت تغییرناپذیر هر اقدامی که پول جابه‌جا می‌کند یا وضعیت کاربر را تغییر می‌دهد؛ در همان تراکنشِ خودِ تغییر نوشته می‌شود.
- **RateBucket (سهمیه درخواست):** محدودیت تعداد درخواست هر کاربر، در دیتابیس تا در ری‌استارت و بین چند نمونه از ربات حفظ شود.
- **Session (نشست‌ها):** وضعیت گام‌به‌گام ویزاردها. این جدول باعث می‌شود ری‌استارت یا استقرار مجدد، کاربرانی را که در میانه احراز هویت یا ثبت معامله هستند از فرآیند خارج نکند.

## 🧪 تست و یکپارچگی مداوم (CI)

```bash
npm run typecheck   # بررسی نوع‌ها با TypeScript
npm test            # اجرای تست‌ها
```

تست‌های داخل پوشه `tests/integration` به یک پایگاه داده واقعی نیاز دارند و در صورت
تنظیم‌نبودن متغیر `DATABASE_URL` به صورت خودکار نادیده گرفته می‌شوند. برای اجرای آن‌ها:

```bash
export DATABASE_URL="postgresql://postgres:postgres@localhost:5432/danmark_test?schema=public"
npx prisma migrate deploy
npm run test:integration
```

گردش‌کار `.github/workflows/ci.yml` در هر push و هر Pull Request این موارد را بررسی می‌کند:
بررسی نوع‌ها، اعمال مایگریشن‌ها روی یک دیتابیس تمیز، اجرای کامل تست‌ها، بررسی امنیتی
وابستگی‌های محیط تولید و اطمینان از عدم انحراف (drift) اسکیما از مایگریشن‌ها.

## 🔼 راهنمای ارتقا از نسخه‌های قبلی

نسخه‌های قبلی این پروژه هنگام اجرا از دستور `prisma db push` استفاده می‌کردند. این دستور
اسکیما را مستقیماً روی دیتابیس زنده اعمال می‌کند و می‌تواند بدون هشدار ستون‌ها را حذف کند.
از این پس مایگریشن‌های نسخه‌بندی‌شده در `prisma/migrations` مرجع هستند و با
`prisma migrate deploy` اعمال می‌شوند.

⚠️ **اگر از قبل یک دیتابیس فعال دارید که جدول‌های آن با `db push` ساخته شده است**، اجرای
`migrate deploy` روی آن با خطا مواجه می‌شود، چون جدول‌ها از قبل وجود دارند. یک بار و فقط
یک بار، مایگریشن اولیه را به عنوان «اعمال‌شده» علامت بزنید:

```bash
npx prisma migrate resolve --applied 20260101000000_init
```

⚠️ **مهاجرت `20260914000000_ledger_integrity`:** این مهاجرت کلیدهای خارجی را از
`CASCADE` به `RESTRICT` تغییر می‌دهد تا حذف یک کاربر نتواند سوابق معاملهٔ طرف مقابل را
پاک کند. روی دیتابیس فعلی شما بدون از دست رفتن داده اعمال می‌شود و آزمایش شده است،
اما پس از آن حذف مستقیم کاربر از دیتابیس دیگر ممکن نیست؛ بستن حساب باید از طریق
`closeAccount()` انجام شود که اطلاعات شخصی را پاک می‌کند و سابقه معاملات را نگه می‌دارد.

سپس برای ساخت جدول جدید `Session` (که در این نسخه اضافه شده است) مایگریشن‌ها را اعمال کنید:

```bash
npx prisma migrate deploy
```

روی یک دیتابیس تازه و خالی به هیچ اقدام اضافه‌ای نیاز نیست و `migrate deploy` همه چیز را
از ابتدا می‌سازد.

## ⚠️ نکات امنیتی و سلب مسئولیت
این ربات صرفاً برای ثبت پیشنهادها و ارجاع خریداران و فروشندگان به ادمین جهت نهایی‌سازی معامله طراحی شده است و فاقد درگاه بانکی یا کیف پول داخلی است. لذا انجام تراکنش‌های مالی، انتقال وجه یا ارز تحت نظارت ادمین و به عهده طرفین بوده و ربات هیچ‌گونه مسئولیتی در قبال صحت انجام تراکنش‌ها ندارد.
ویژگی ویرایش پیام در گروه کمک می‌کند تا پیشنهادهای قدیمی بلافاصله غیرفعال نمایش داده شده و از بروز سوءاستفاده‌های احتمالی جلوگیری شود.

🛡️ **درباره مخدوش‌سازی خودکار مدارک:** ربات تلاش می‌کند شماره شناسایی دانمارکی (CPR)،
کد پستی و نام خیابان را با استفاده از OCR تشخیص داده و بپوشاند. این قابلیت **تضمینی
نیست**: اگر الگویی تشخیص داده نشود یا پردازش تصویر با خطا مواجه شود، ربات صراحتاً به
کاربر اطلاع می‌دهد که تصویر **بدون مخدوش‌سازی** ارسال خواهد شد. مسئولیت نهایی پوشاندن
اطلاعات حساس بر عهده کاربر است.
